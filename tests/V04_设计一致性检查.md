# V04 设计一致性检查清单

版本 v1.0 · 2026-11-09 · 来源：D03 第 2 章

## 1 自动检查（每次改动后运行）

```bash
python3 tools/skilltool.py all
python3 tools/validate_repo.py
```

| 工具 | 检查内容 |
|---|---|
| skilltool validate | frontmatter 只有 name、description；name 格式；SKILL.md 九项齐全；引用的文件存在；同步副本与源文件一致；包内文件名只用 ASCII；SKILL.md 长度 |
| validate_repo | 编号引用在定义范围内；场景编号在路由表、场景卡、D03 三处一致；路由表指向的场景卡存在；文档相对链接有效；manifest 中的文件存在；没有写入密钥 |

## 2 人工检查（重大改动后）

| 编号 | 检查 | 方法 |
|---|---|---|
| CK01 | 目标覆盖 | G1–G7 逐项找对应机制（D03 §2.1） |
| CK02 | 原则符合 | 九条原则逐条找反例 |
| CK03 | 分工一致 | 每个 Skill 步骤都有层级；GPT 承担的都属于 T1；执行层承担的都属于 T2 |
| CK04 | 平台兼容 | 有没有只能在某个平台运行的环节；特定能力是否有替代 |
| CK05 | 事实唯一 | 权威位置表（D03 §2.2）中每类事实只有一个位置 |
| CK06 | 闭环 | 每个产出有保存位置和回写去向；每个状态有升级人；每个资产有维护人 |
| CK07 | 精简 | 首批每项都说得出不可省的理由 |
| CK08 | 前期衔接 | D01 附录 A 的对应仍然成立 |
| CK09 | 编号无冲突 | 前缀表（D03 §2.4） |
| CK10 | 使用体验 | 每个角色每天要做的事、要记住的口令 |
| CK11 | 通用与场景分离 | 通用规则里没有某个场景特有的步骤；场景卡和模式文件没有复制通用规则原文，只引用编号 |
| CK12 | 路由精准 | 每个场景都有唯一的触发与判别要点；易混淆的场景都有判别规则；路径的每一步都写明 Skill、模式、层级、产出 |
