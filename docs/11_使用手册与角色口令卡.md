# 使用手册与角色口令卡

版本 v1.0 · 2026-11-09 · D11 · 给全体员工

---

## 1 先记住三件事

1. **项目的事实都在项目主卡里。** 打开项目文件夹的 `00_项目主卡.md`，就能看到项目现在的条件、方向、待确认事项和当前有效的文件。
2. **用一句话发起任务。** 说清"哪个项目＋要做什么"，例如"018 客户改了人数，查影响"。AI 会自己判断这是哪类工作、该用哪个工具、交给哪个平台。
3. **该你确认的，AI 会停下来等你。** 对外报价、发送文件、选供应商、确认变更、签约、预订付款，都要人点头。AI 只准备材料和建议。

---

## 2 三个平台怎么分工

| 平台 | 做什么 | 你什么时候用 |
|---|---|---|
| WorkBuddy | 日常的整理、填表、写文件、归档、提醒、周报；正式文件由它保存 | 大部分日常工作；在企业微信里直接找它 |
| 豆包 | 文案：邀请函、行前通知、主持词、宣传稿、回复客户的草稿；手机上的快速记录 | 写对客文字；在现场用手机 |
| GPT | 难的判断和创意：读标书、出策划方向、审方案、处理复杂变更、做主视觉和改图 | WorkBuddy 提示"需要交给 GPT"时，把它准备好的任务包带过去 |

一个项目的正式文件只由一个平台保存，避免出现两个"最终版"。

---

## 3 一个任务是怎么走的

1. 你说一句话（或者群聊记录、文件自动进来）。
2. AI 认出项目和工作类型（场景），按固定的路径一步步做。
3. 遇到难的判断，WorkBuddy 会打包一个"任务包"，请你带到 GPT 里处理。
4. 遇到需要你确认的事，AI 停下来，写清楚需要谁确认什么。
5. 结束时，AI 写一张"交接卡"（放在项目的 `_任务/` 里），记下做了什么、下一步是什么。

---

## 4 每天要确认的东西：更新建议单

群聊记录每天两次自动进来（中午和傍晚），WorkBuddy 会为每个有新消息的项目生成"更新建议单"：

- **需确认**：人数、日期、地点、预算、服务内容的变化，客户的决定，变更，待办。只有这部分需要你看并确认。
- **仅记录**：背景、偏好、资源和报价线索。不用逐条确认。

客户说"可能""考虑""大概"的，一律是"待确认"，不会被当成定了。

## 5 角色口令卡

### 5.1 项目经理

| 什么时候 | 说什么 |
|---|---|
| 来了新项目 | "新建项目：某银行 3 月高峰会" |
| 每天上午 | "看看今天各项目的更新建议" |
| 想了解项目 | "018 现在什么情况" |
| 客户提了改动 | "018 客户改了人数，查影响" |
| 群里消息不知道归哪个项目 | "这条消息是哪个项目的" |
| 发文件前 | "发送前检查 018 全部文件" |
| 中标或入围了 | "018 中标了" |

你要确认：更新建议单的"需确认"部分、变更是否成立、对客文件发送、项目阶段变化。

### 5.2 策划

| 什么时候 | 说什么 |
|---|---|
| 要出方向 | "给 018 出三个方向"（WorkBuddy 会准备任务包，带到 GPT） |
| 方向选定后 | "按方向 B 细化行程／议程／课表" |
| 要视觉 | "做 018 的风格卡和主视觉" |
| 客户说"再高级一点" | "客户说要更高级但预算不变，怎么调" |
| 要成文 | "按方案结构出方案文档／对客 PPT" |
| 要延展物料 | "按风格卡出海报和朋友圈图" |

你要确认：方向选择（与负责人一起）、视觉。

### 5.3 资源采购

| 什么时候 | 说什么 |
|---|---|
| 要询价 | "做 018 的询价单" |
| 看行情 | "上携程看看杭州 12 月的酒店价格" |
| 收到报价 | "录入 018 的酒店报价并比较" |
| 要算钱 | "按 80、100、120 人测算" |
| 供应商变了 | "酒店涨价了，看影响" |
| 订好了 | "酒店已经订了，更新报价状态" |

你要确认：发出询价、价格状态升级（已核可用、已锁定）、资源档案的评价。

### 5.4 商务投标

| 什么时候 | 说什么 |
|---|---|
| 来了招标文件 | "这个标看一下" |
| 判断投不投 | "这个标值不值得投" |
| 查资格 | "我们资质够不够" |
| 收到答疑 | "这是 018 的答疑文件，更新需求" |
| 做标书 | "按招标目录组装投标文件" |
| 提交前 | "发送前检查 018 全部文件" |

你要确认：澄清问题是否发出、补证、标书提交（与负责人一起）、证据库的维护。

### 5.5 执行

| 什么时候 | 说什么 |
|---|---|
| 准备执行 | "生成 018 执行手册" |
| 发通知 | "写 018 的行前通知" |
| 现场出状况 | "018 户外拓展因雨改室内，查影响" |
| 记录异常 | "记录现场异常：……" |
| 结束后 | "准备 018 的结算资料" |

名单、分房、分车只在表格里处理，不要把名单发到群里或交给 GPT。

### 5.6 负责人与财务

| 什么时候 | 说什么 |
|---|---|
| 看全局 | "出本周项目周报" |
| 看投标情况 | "出本季度投标统计" |
| 项目复盘 | "018 结项复盘" |
| 看客户 | "这个客户下次可能做什么" |

你要确认：投不投、方向、对外报价、低于最低安全报价的批准、重大变更、标书提交、签约、验收结算、案例能否对外使用。

### 5.7 AI 协同负责人

| 事项 | 做法 |
|---|---|
| 新群 | 在名册中登记群与项目的映射 |
| 平台出问题 | 换平台或降级执行，见 adapters/ 下的说明 |
| 版本更新 | 按 D08 第 4 节发布，更新兼容矩阵 |
| 收集问题 | 设计外的情况记入 RG01 扩展登记 |
| 乐享 | 维护映射表（D05 §2.3），执行验证清单（D12 §8） |

---

## 6 查公司资料

直接问："我们做过类似的研学吗""资质证书在哪""公司介绍发我"。AI 会先查业务库和乐享，回答时注明出处和能否对外使用；查不到会直接说查不到。

---

## 7 不要做的事

- 不要把名单、证件号、手机号发给 GPT。
- 不要让两个平台同时改同一份正式文件。
- 不要手动改 AI 生成的"关键数据"块里的数字；要改先改主卡。
- 不要把乐享的令牌、账号密码写进文件或发到群里。
- 不要直接改主卡里"已确认"的内容而不留来源。

---

## 8 常见问题

| 问题 | 回答 |
|---|---|
| AI 认错了项目或工作类型怎么办？ | 直接纠正："不是这个，是 018 的报价变化"。 |
| GPT 用不了怎么办？ | WorkBuddy 会"降级执行"，结果第一行标"未经 T1 审查"，由负责人决定是否采用。 |
| 怎么知道哪份文件是最新的？ | 看主卡第 7 节"版本指针"。 |
| 金额对不上怎么办？ | 以成本测算表为准；说"发送前检查 018 全部文件"。 |
| 遇到系统没覆盖的情况？ | 照常处理，AI 会在日志里标"设计外"，AI 协同负责人定期整理。 |
