# 乐享知识库接入方案

版本 v1.0 · 2026-11-09 · D12

---

## 0 结论

- **可行。** 乐享有官方 MCP 服务（官方仓库 `tencent-lexiang/lexiang-mcp-server`，38 个工具），能检索、读取、创建和编辑知识条目、上传下载文件、导入腾讯会议录制。权限跟随登录账号：只能访问该账号有权限的知识库。
- **接入地址在线，认证是标准做法。** 用你给的地址做了不带凭证的探测：返回 401 和标准的 MCP 授权指引；授权服务器支持授权码加 PKCE、刷新令牌和动态注册客户端。也可以改用乐享"会话管理"里生成的 access_token。
- **三个平台都有接入路径**，但对 OAuth 登录的支持程度不同，需要逐个实测（第 4 章）。不支持 OAuth 的平台用 access_token；完全不能连接的平台，由能连接的平台检索后放进任务包。
- **你贴的配置需要补一项**：`company_from=` 是空的，必须填企业的乐享 code（登录乐享后在 lexiangla.com/mcp 获取），否则会报"需要授权"。`preset=meta` 在公开文档里没有出现；文档写明"不指定 preset 时返回 4 个元工具（列出工具分类、搜索工具、获取参数、调用工具）"，`meta` 很可能对应这组元工具，登录后列出工具即可确认。
- **还没做的验证**：需要企业账号登录后才能做的端到端测试（列工具、检索、读取、写入沙盒）。第 8 章是验证清单，`tools/lexiang_probe.py` 是只读验证脚本；由你登录后执行，或授权我在本会话里连接后执行。
- **定位建议**：乐享先作为"公司知识来源"只读接入；试点后再决定是否让它承载部分共享资产；项目工作区暂不放进乐享（第 3 章）。

## 1 验证过程与结果

| 项目 | 方法 | 结果 |
|---|---|---|
| 官方说明 | 读官方仓库的 README、server.json、CHANGELOG | 38 个工具分 7 类；两种认证方式；preset 参数；"只能访问有权限的知识库"；文件上传分三步；支持文档审批流，AI 生成内容可先进入待审核状态 |
| 接入地址 | 用你给的地址发送不带凭证的 initialize 请求 | HTTP 401；返回 `WWW-Authenticate: Bearer resource_metadata=…`；说明服务在线，并按 MCP 授权规范要求登录 |
| 资源元数据 | 读取 `/.well-known/oauth-protected-resource` | 授权服务器为 mcp.lexiang-app.com；scope 为 mcp、api；令牌放在请求头 |
| 授权服务器元数据 | 读取 `/.well-known/oauth-authorization-server` | 授权码模式；PKCE（S256）；支持刷新令牌；动态注册 `/oauth/register`；撤销 `/oauth/revoke`；公共客户端无需密钥 |
| 第三方收录 | mcp.so、glama 等 | 与官方一致；个别页面对 preset 的描述前后矛盾，以登录后实际返回的工具为准 |
| 平台连接能力 | 查 WorkBuddy、豆包工作、ChatGPT 的公开资料 | 都能连接远程 MCP；OAuth 支持各不相同 |

探测只发送了协议初始化请求，没有发送任何账号、令牌或业务数据。

## 2 乐享 MCP 能做什么

| 类别 | 工具 | 读或写 | 本体系的用法 |
|---|---|---|---|
| 搜索 | `search_kb_search`（关键词）、`search_kb_embedding_search`（语义） | 读 | 默认使用 |
| 条目读取 | `knowledge_describe_entry`、`knowledge_describe_ai_parse_content`、`knowledge_list_children`、`knowledge_list_parents`、`knowledge_list_latest_entries`、`knowledge_diff_entry_content`、`knowledge_search_udf_entries` | 读 | 默认使用 |
| 知识库与团队 | `knowledge_list_spaces`、`knowledge_describe_space`、`teamspace_list_teams`、`teamspace_describe_team`、`teamspace_list_some_teams` | 读 | 用于建立映射、定位内容 |
| 文件读取 | `knowledge_describe_file`、`knowledge_download_file` | 读 | 默认使用 |
| 会议录制 | `connector_list_tx_meeting_records`、`connector_search_tx_meeting_records`、`connector_describe_tx_meeting_record` | 读 | 【预留】作为会议纪要来源 |
| 条目写入 | `knowledge_create_entry`、`knowledge_import_content`、`knowledge_move_entry`、`knowledge_rename_entry` | 写 | 只在"AI 产出区"使用，需人工确认 |
| 文档块编辑 | `block_create_block_descendant`、`block_update_block`、`block_update_blocks`、`block_move_blocks`、`block_delete_block`、`block_delete_block_children`、`block_describe_block`、`block_list_block_children` | 写（含删除） | 默认不用；删除类一律禁止 |
| 知识库创建 | `knowledge_create_space` | 写 | 不用 |
| 文件上传 | `knowledge_apply_upload` → MCP 之外的 HTTP PUT → `knowledge_commit_upload`；`knowledge_create_hyperlink` | 写 | 【预留】 |
| 外部导入 | `connector_import_tx_meeting_record`、`connector_reload_tx_meeting_record`、`connector_import_iwiki_doc` | 写 | 【预留】 |

注意：没有删除条目的工具，但块编辑工具可以删除文档内容。

## 3 在本体系中的定位

### 3.1 三种角色

| 角色 | 承载的内容 | 建议 |
|---|---|---|
| A 公司知识来源（只读） | 已经在乐享里的公司资料：公司介绍、资质证照、制度流程、产品与服务介绍、历史案例、培训资料 | 现在就做 |
| B 部分共享资产的宿主 | 能力与证据库的原件（A05）、方案素材库（A07）、客户档案（A06）、复盘与案例 | 试点后看效果再决定 |
| C 业务库宿主 | 项目工作区（主卡、日志、成本表等） | 暂不建议：项目记录读写频繁、成本表要靠表格公式计算，放在文件里更稳；等角色 B 稳定后再评估 |

### 3.2 怎样保持"事实只存一处"

- 已经在乐享里的类别，在映射表里登记"权威位置 = 乐享"。业务库不再存这类内容的副本，只存引用：乐享条目名称、链接、更新时间。
- 不能连接乐享的平台用"快照"：由能连接的平台把需要的段落导出为 Markdown 放进任务包，标注"乐享快照｜条目名｜导出时间"。快照只读、随任务使用，不作为权威。
- 业务库和乐享都有的同类内容，在建立映射时选定一个权威位置，另一处改为引用。

### 3.3 映射表（首次接入时建立，正式表在 D05 §2.3）

| 字段 | 说明 |
|---|---|
| 乐享知识库或目录 | 名称和链接 |
| 内容类别 | 例如资质证照、历史案例、制度流程 |
| 对应本体系资产 | 例如 A05、A07，或"仅作参考" |
| 权威位置 | 乐享或业务库 |
| 数据级别 | L1–L4（D07） |
| 可访问的平台 | GPT、WorkBuddy、豆包 |
| 维护人 | |
| 备注 | 例如是否允许对外使用 |

建立步骤：列出知识库（`knowledge_list_spaces`）→ 逐个查看目录（`knowledge_list_children`）→ 归类 → 确定权威位置和数据级别 → 写入映射表 → 按映射设置 AI 账号权限。

## 4 各平台接入方式

| 平台 | 方式 | 认证 | 已知限制 | 状态 |
|---|---|---|---|---|
| GPT · ChatGPT | 开发者模式下添加自定义连接器，填写乐享接入地址 | OAuth（乐享支持动态注册客户端） | 第三方资料显示需要企业或团队版管理员开启，部分套餐只能读；该功能仍在测试阶段；内容会进入境外服务 | 待实测 |
| GPT · Codex | 在 Codex 的 MCP 配置中添加远程服务器 | OAuth 或 access_token | 版本之间有差异 | 待实测 |
| WorkBuddy | `mcp.json` 中添加 http 类型的服务器，或使用"自定义连接器" | 有资料显示支持 OAuth 授权（点 Connect），也有资料显示只支持 Bearer 请求头；乐享两种都支持 | 同属腾讯的 CodeBuddy 插件版需要用 `mcp-remote` 桥接 | 待实测，首选平台 |
| 豆包工作 | 插件·技能·伙伴 → 连接器 → 新建自定义连接器（HTTP） | 没有找到 OAuth 说明；可用 access_token 参数 | 缺少官方文档 | 待实测 |
| 不能连接时 | 由 WorkBuddy 检索后，把摘录放进任务包 | — | — | 兜底 |

各平台的配置示例（不含任何令牌）见 `adapters/lexiang/连接配置示例.md`。

## 5 权限与安全

- **账号**【默认】：每个员工用自己的乐享账号授权，权限和操作记录跟随个人；不共用账号。如果给 GPT 开连接，建议用单独的低权限账号，只开放 L1、L2 级知识库。
- **最小权限**：AI 默认只用读类工具。写入只发生在指定的"AI 产出区"知识库，并进入乐享的审核流程，由人发布。
- **preset 的作用有限**：preset 可以缩小工具范围，但现有预设里没有"只读"一档，所以只读要靠账号权限和 Skill 规则来保证。
- **令牌是密钥**：access_token 不写进方法库，不放进任务包，不发到群里，只保存在各平台的连接配置里。人员离职或令牌泄露时，在乐享会话管理中作废（服务端有撤销接口）。
- **数据级别**：乐享知识库按 L1–L4 标注；GPT 的连接只能访问 L1、L2（D07 §5）。
- **写入风险**：块编辑工具可以删除内容，AI 一律不调用 `block_delete_block` 和 `block_delete_block_children`。更新已有文档时要明确"在原文档上更新"，避免重复建文档（官方常见问题里的提示）。

## 6 Agent 使用规则

正式规则写在通用规则里：权威位置与映射表见 D05 §2，数据准入见 D07 §5，检索步骤见 D06 §3.4。要点：

1. 需要公司资料时，先查映射表确定权威位置。
2. 权威位置是乐享，且本平台已连接：用 `search_kb_search` 或 `search_kb_embedding_search` 检索，用 `knowledge_describe_ai_parse_content` 读取正文。
3. 本平台未连接：在交接卡里写明需要的资料，由已连接的平台补充快照。
4. 引用时注明"乐享｜条目名｜更新时间"。
5. 检索不到时如实写"乐享中未检索到"，不编造；不确定的结果不当作事实。
6. 不把乐享内容整篇复制进业务库。
7. 写入只在 AI 产出区，并需要人确认。

## 7 实施步骤

1. 管理员提供企业乐享 code；确定"AI 产出区"知识库，以及各知识库的数据级别。
2. 在一个平台（建议 WorkBuddy）完成授权连接，执行第 8 章的验证清单。
3. 建立映射表，写入 D05 §2.3。
4. 在其他平台重复连接与验证，结果记入 `adapters/兼容矩阵.md`。
5. 试点中观察：检索命中率、引用是否正确、权限是否符合预期。
6. 根据试点结果，决定是否启用第 3.1 节的角色 B。

## 8 验证清单

| 编号 | 验证项 | 方法 | 通过标准 |
|---|---|---|---|
| V-LX01 | 连接 | 在平台中完成授权，列出工具 | 返回工具列表或 4 个元工具 |
| V-LX02 | preset | 分别用 `meta`、`knowledge` 和不填 | 记录各自返回的工具 |
| V-LX03 | 列知识库 | `knowledge_list_spaces` | 只出现该账号有权限的知识库 |
| V-LX04 | 关键词检索 | 用一个已知文档的标题检索 | 命中目标文档 |
| V-LX05 | 语义检索 | 用描述性的问题检索 | 前 5 条里包含目标文档 |
| V-LX06 | 读取正文 | `knowledge_describe_ai_parse_content` | 返回正文，格式可用 |
| V-LX07 | 权限隔离 | 用无权限的账号检索受限内容 | 检索不到 |
| V-LX08 | 写入（沙盒） | 在 AI 产出区用 `knowledge_import_content` 导入一篇测试文档 | 进入待审核，或只出现在沙盒中 |
| V-LX09 | 令牌失效 | 作废会话后再调用 | 返回 401 |

`tools/lexiang_probe.py` 可以执行 V-LX01、V-LX03、V-LX04、V-LX06（只读）。使用方法见脚本开头的说明；令牌只从环境变量读取，不写入任何文件。
