# 需求与标书解析：模式

版本 v1.0 · 方法层 · 属于 brief-analysis（S02）

---

## M1 全量模式（招投标）

适用：SC01。

| 步 | 动作 | 层级 |
|---|---|---|
| 1 | 文件清单：采购文件、附件、澄清与答疑，记录版本和页数；扫描件识别 | T2 |
| 2 | 基本信息：采购方式、截止时间与递交方式、预算或最高限价、评标方法、保证金 | T2 |
| 3 | 资格条件：逐条列出，转 M6 核对 | T2 |
| 4 | 实质性条款与废标风险：★号条款、不允许偏离的条款、废标情形、格式、签章、报价唯一性（对照 bid-checklist.md） | T1 |
| 5 | 评分拆解：每个评分项的分值、评分方式、得分要点，对应到方案章节和证据 | T1 |
| 6 | 需求矩阵：逐条需求 → 服务模块 → 响应要点 → 是否可以承诺 → 证据 | T2 |
| 7 | 澄清问题：只列影响方案、报价或资格判断的问题 | T1 |
| 8 | 参与判断要点：转 M4 | T1 |

## M2 快速模式（框架订单）

适用：SC02。

| 步 | 动作 | 层级 |
|---|---|---|
| 1 | 读 A06：框架资格、有效期、考核要求、评审偏好 | T2 |
| 2 | 在 A01 中找最近 3 个同客户、同产品族的项目；读它们的主卡和中选方案 | T2 |
| 3 | 差异表（TP06 快速模式附表）：时间、地点、人数、标准、特别要求、比选方式、评分规则 | T2 |
| 4 | 差异涉及评分规则、资格或新的服务模块时，升级分析 | T1 |
| 5 | 复用清单：可以沿用的方案章节、报价、供应商（核对报价有效期） | T2 |
| 6 | 主卡更新建议 | T2 |

没有可比的历史订单时，改用 M1。

## M3 澄清模式（直客）

适用：SC03。

1. 读沟通摘要和主卡。〔T2〕
2. 按主产品族策划卡的"必问问题"，对照已知和未知。〔T2〕
3. 客户目标含糊时，判断可能的主目标（D05 §8.3），标"推断"。〔T1〕
4. 写澄清问题：不超过 8 个，按对方案影响的大小排序，每个写明为什么问。〔T2〕
5. 建议问法：口语化，适合在群里或电话里问。〔T2〕

## M4 参与判断

适用：SC01 第 4 步、SC10。〔T1〕

按十个维度判断，每个维度写判断和依据：

| 维度 | 看什么 |
|---|---|
| 客户关系 | 是否真实接触过；有没有决策人联系 |
| 资格满足 | M6 的结论 |
| 需求匹配 | 是否在公司的产品族和服务模块范围内 |
| 可验证案例 | A05 中已交付及以上的同类业绩 |
| 资源可得 | 关键资源（场地、讲师、档期）能否拿到 |
| 价格风险 | 最高限价与粗略成本；是否明显低价竞争 |
| 预计毛利 | 需要时用 sourcing-costing M4 粗测，标"估算" |
| 产能占用 | 与在办项目的时间冲突 |
| 战略价值 | 新客户、新领域、框架资格 |
| 复购可能 | 客户的采购周期与历史 |

结论：参与／不参与／有条件参与（写明条件）。由负责人决定。

## M5 答疑更新

适用：SC12。

1. 逐条比较答疑或澄清内容与需求矩阵。〔T1〕
2. 标出新增、修改、删除的条目，注明原文页码。〔T2〕
3. 需求版本号加一，生成新版 TP06。〔T2〕
4. 影响已有成果（方案、报价、标书）时，列出文件，转 change-review M1。〔T1〕

## M6 资格与证据核对

适用：SC01 第 3 步、SC11。〔T2〕

1. 资格条件逐条对照 A05（或乐享中登记的权威位置）。
2. 每条核对：是否有证据；有效期是否覆盖截止日；适用主体是否为投标主体；证据状态（业绩必须是"已交付"及以上）。
3. 输出：满足、缺口、补证建议（合作方资质、补开证明等），以及证据编号清单。
4. 即将过期的证据，建议列入待办。
