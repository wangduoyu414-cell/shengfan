# 场景卡 F：修改与变更

版本 v1.0 · 场景层 · 属于 project-hub（S00）

一般与重大的界线见 D06 §4.1 第 3 条；不确定时按重大处理。

---

## SC30 客户小修改

- **触发**："这页改一下""换个说法""加一张图"。
- **判别**：不触及重大变更阈值；不改变人数、日期、地点、预算和服务模块。
- **路径**：
  1. S05 对应模式〔T2〕在当前版本上修改，版本号加一
  2. S06·M3〔T3、T2〕只核对修改涉及的关键数据
  3. 【人】项目经理确认后发送
- **回写**：主卡版本指针；日志"事件：小修改"。

## SC31 重大变更

- **触发**："人数改到 55""改日期""加一场晚宴""预算降了"。
- **判别**：触及 D06 §4.1 第 3 条阈值，或不确定是否触及；项目阶段不是"执行中"（执行中走 SC37）。
- **前置**：变更原话的来源；确认状态（客户只是"考虑"时仍为"待确认"）。
- **路径**：
  1. S06·M1〔T1〕变更影响单（TP04）：涉及的模块 → 资源、成本、日期、已预订资源与取消损失、承诺、安全 → 需要重新核实的事项 → 需要修改的文件
  2. 【人】项目经理确认变更是否成立、是否需要重新报价
  3. S04·M1、M4〔T2、T3〕重新询价和测算 → 成本测算新版本
  4. S05 对应模式〔T2〕按待改清单修改全部文件
  5. S06·M3〔T3、T2〕一致性终检
  6. 【人】确认后发送新版本
- **回写**：主卡（旧值作废，新值待确认或已确认）；日志"变更"；版本指针。
- **注意**：变更只是"待确认"时，可以先做影响分析，不改正式文件。

## SC32 发送或提交前终检

- **触发**："发之前检查一下"。
- **判别**：任何对外文件发出前。
- **路径**：
  1. S06·M3〔T3、T2〕按版本指针核对全部当前有效文件的关键数据；标书加做废标项核对
  2. 【人】确认后发送
- **回写**：检查结果写入交接卡。
