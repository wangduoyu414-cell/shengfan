# 场景卡 A：进入与信息

版本 v1.0 · 场景层 · 属于 project-hub（S00）

每张卡只写本场景特有的路径和要点。层级见 D06 §1；人工关口见 D06 §7；每一步前都做层级检查和数据检查（D06 §3.1 第 4 步）；结束时按 S00·P5 收尾。

---

## SC01 收到招标公告或采购文件

- **触发**：上传采购文件或招标公告；"这个标看一下"。
- **判别**：有正式采购文件，且不是框架内的二次比选（否则 SC02）。
- **前置**：采购文件完整（含附件、澄清）；是否扫描件（需要文字识别时先识别）。
- **路径**：
  1. S00·P1〔T2〕新建项目，入口类型"招投标"，原件存 01_原始资料 → 工作区、主卡初稿
  2. S02·M1〔T1 解读；T2 填表〕资格、评分、实质性条款、废标风险、截止时间、需求矩阵、澄清问题 → TP06
  3. S02·M6〔T2〕资格条件逐条对照 A05：有效期、主体、证据状态 → 资格缺口
  4. S02·M4〔T1〕参与判断要点与建议 → TP06 第 7 节
  5. 【人】负责人决定投不投；投 → 按主产品族转 SC13–SC16；不投 → 阶段"放弃"，转 SC40（简版）
- **回写**：A01 新增一行；主卡（截止时间、硬性要求、评分要点、待确认）；日志"决定：投标／放弃"。
- **分支**：澄清问题需要发出 → 列入待确认，由人决定是否发出；资格不满足且无法补证 → 建议放弃。
- **注意**：截止时间写进主卡"下一节点"，并列入周报。

## SC02 框架客户的二次比选或询价

- **触发**：框架客户群里出现新需求；上传比选或询价通知。
- **判别**：客户在 A06 有有效的框架资格，需求在框架范围内（否则 SC01）。
- **前置**：框架资格有效期；本次比选方式（价格优先还是综合评分）。
- **路径**：
  1. S00·P1〔T2〕新建项目，入口"框架内订单"，所属框架填框架项目编号；在 A08 把新项目加入该群的活跃项目 → 工作区、主卡初稿
  2. S02·M2〔T2；差异涉及评分、资格或新模块时 T1〕与最近 3 个同客户同类项目比对 → 差异表（TP06 快速模式附表）、复用清单
  3. S04·M2、M4〔T2、T3〕查 A04 同城同类的有效报价，过期的转 S04·M1 询价；复制测算表测算 → 成本测算 V1
  4. S05·M1、M4〔T2；差异部分 T1 审查〕以上次中选方案为底稿改写方案和报价单 → 方案 V1、报价单 V1
  5. S06·M3〔T3、T2〕一致性终检 → 检查结果
  6. 【人】负责人审批报价并发送
- **回写**：A01 新增一行（所属框架）；主卡；A04 新报价；日志"提交"。
- **分支**：没有可比的历史订单 → 第 2 步改用 S02·M1；客户要求新创意 → 第 3 步前插入 S03·M1 与【人：选方向】。
- **注意**：首版目标 48 小时内【默认】。

## SC03 直客提出新需求

- **触发**：客户在群里、电话里或会面时提出想法。
- **判别**：没有采购文件，需求含糊（有采购文件时按 SC01）。
- **前置**：沟通内容已摄取或已手工投递。
- **路径**：
  1. S01·M2〔T2〕整理这次沟通 → 更新建议单
  2. S00·P1〔T2〕新建项目，入口"直接委托" → 工作区、主卡初稿
  3. S02·M3〔T2；目标含糊时 T1〕按主产品族策划卡的"必问问题"对照已知和未知 → 澄清问题（不超过 8 个，按影响排序）
  4. 【人】项目经理决定怎样发问
- **回写**：主卡（已知条件均为"待确认"）；待确认事项；日志"事件：新需求"。
- **分支**：信息已经足够 → 直接转 SC13–SC16；客户是框架客户且需求在框架内 → 改走 SC02。

## SC04 群聊摄取后的项目更新

- **触发**：定时摄取批次写入 02_沟通记录（D04 §10）。
- **判别**：事件触发，处理的是批量消息。
- **前置**：主卡"沟通记录已处理到"的位置。
- **路径**：
  1. S01·M1〔T2；冲突和含糊处 T1〕只读新增部分，分为"需确认"和"仅记录" → 更新建议单（TP05）
  2. 【人】项目经理确认"需确认"条目
  3. 主执行平台〔T2〕把已确认的条目写入主卡、日志、资产；更新处理位置
  4. 按建议单的触发转场景：冲突 → SC07；小修改 → SC30；重大变更 → SC31；报价线索 → SC22
- **回写**：主卡、日志、A04、A06、A08（都在人确认之后）。
- **注意**：没有新增内容时，只更新处理位置，不生成建议单。

## SC05 收到文件

- **触发**：群里或邮件中收到需求表、名单、报价单、合同、图片等文件。
- **判别**：以单个文件为主（批量消息走 SC04）。
- **前置**：确定文件属于哪个项目。
- **路径**：
  1. S01·M3〔T2〕定级（D07 §1），按 D05 §6.2 命名后存入 01_原始资料，提取要点 → 更新建议单
  2. 按文件类型分流：报价单 → SC22；名单 → 按 L4 处理，只在表格中使用（D07 §2）；合同 → SC34；采购答疑 → SC12
  3. 【人】确认归档与级别
- **回写**：01_原始资料；主卡（相关条件，待确认）。

## SC06 线下会议或电话沟通

- **触发**："刚跟客户开完会""电话里说……"；会议纪要、录音转写、截图。
- **判别**：人手动投递的材料（定时摄取走 SC04）。
- **前置**：投递时注明项目编号；会议已录制并导入乐享的，可从乐享读取纪要【预留】。
- **路径**：
  1. S01·M4〔T2〕整理为统一格式，按 S01·M1 的规则分类 → 更新建议单
  2. 【人】项目经理确认
- **回写**：02_沟通记录（纪要）；主卡；日志。

## SC07 说法冲突或前后矛盾

- **触发**：更新建议单中的冲突项；"他们说的不一样"。
- **判别**：同一事项出现两个以上的值。
- **路径**：
  1. S01（建议单冲突栏）〔T2〕列出各方说法和来源
  2. 〔T1〕判断冲突影响什么（方案、报价、承诺）、该向谁确认（看 A08 的决策角色）
  3. 【人】项目经理向对应的人确认
- **回写**：确认前，两个值都保持"待确认"；确认后，旧值改为"作废"。

## SC08 一个群对应多个在办项目

- **触发**：待归属清单；"这条是哪个项目的"。
- **判别**：群在 A08 中有多个活跃项目。
- **路径**：
  1. S01·M5〔T2〕根据日期、地点、人数、项目名、引用关系给出归属建议和理由
  2. 【人】项目经理确认归属
- **回写**：统一消息记录的 attribution 改为"confirmed"；进入对应项目的摘要和建议单。

## SC09 新人或另一个平台接手项目

- **触发**："我接手 018"；"018 现在什么情况"。
- **判别**：要了解项目全貌，不是做某个具体任务。
- **路径**：
  1. S00·P2〔T2〕读主卡、日志最近 10 条、最近一张交接卡
  2. S00·P6〔T2〕输出项目现状：阶段、有效条件、当前有效文件、待确认、下一节点、风险
- **注意**：验收标准是 10 分钟内说清项目现状（G1）。

## SC47 查询公司资料

- **触发**："我们做过类似的研学吗"；"资质证书在哪"；"公司介绍发我"。
- **判别**：只查资料，不推进具体的项目任务（问某个项目的情况走 SC09）。
- **路径**：
  1. S00·P3〔T2〕按 D05 §2.2、§2.3 确定权威位置：业务库（A05、A07、A01）或乐享
  2. 检索并读取；本平台没有连接乐享时，在交接卡中列出检索词，由已连接的平台补充
  3. 回答并注明来源（D05 §4）；涉及对外使用的，注明"可否对外"
- **注意**：检索不到时如实说明，不编造；不把乐享内容整篇复制到业务库。
