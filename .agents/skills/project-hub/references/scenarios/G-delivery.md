# 场景卡 G：成交与交付

版本 v1.0 · 场景层 · 属于 project-hub（S00）

delivery-settlement（S07）在第四期建成。之前，本组场景先用公司现有的执行和结算表格，由 S05 按现有格式整理。

---

## SC33 中选、入围、成交

- **触发**：中标通知、入围通知、客户确认。
- **判别**：结果到达。
- **路径**：
  1. S00·P5〔T2〕提出阶段更新建议："已中选"或"未中选"
  2. 入围框架时：提出 A06 框架资格更新建议（项目编号、有效期、考核要求）；入围不等于订单（D05 §3.3）
  3. 【人】项目经理确认阶段
  4. 有订单或合同 → SC34；未中选 → SC40
- **回写**：A01 阶段与中选金额；A06；日志"确认"。

## SC34 合同核对与启动

- **触发**："合同来了""项目启动"。
- **判别**：已中选。
- **路径**：
  1. S07·M1〔T1〕合同要点（范围、价格、付款、违约、取消、验收、保密）与投标或方案承诺逐条对照，列出差异
  2. S07·M1〔T2〕启动单、供应商确认清单（TP17 第 1、7 节）
  3. 【人】签约
- **回写**：A01 合同金额；主卡阶段"执行准备"；日志"决定：签约"。

## SC35 供应商确认、预订、付款

- **触发**："订房""付定金""确认车辆"。
- **判别**：需要锁定资源。
- **路径**：
  1. 【人】资源采购预订、付款
  2. S04·M2〔T2〕提出价格状态更新建议："已核可用"或"已锁定"
- **回写**：A04 价格状态（由资源采购确认）；执行手册的供应商确认清单。

## SC36 执行手册与行前

- **触发**："出执行手册""分房分车""发行前通知"。
- **判别**：执行准备阶段。
- **路径**：
  1. S07·M2〔T2；涉及安全的调整 T1〕执行手册（TP17）；名单、分房、分车只在表格中处理，手册里只写编号和数量（L4）
  2. S05·M5〔T2〕行前通知（TP16 B 部分）
  3. S06·M3〔T3、T2〕执行手册、通知与主卡一致
  4. 【人】项目经理确认后发送
- **回写**：06_执行与结算；主卡版本指针。

## SC37 现场异常

- **触发**："下雨了""车晚了""人数变了""酒店房间不够"。
- **判别**：项目阶段为"执行中"。
- **路径**：
  1. S07·M3〔T2〕记录：时间、事件、影响、现场情况
  2. S06·M2〔T1 需要替代方案时；GPT 不可用时降级执行〕15 分钟内给出可选方案：安全、资源可用、客户体验、成本、取消损失
  3. 【人】现场负责人决定
  4. S05·M5〔T2〕需要时出客户通知
- **回写**：日志"事件"与"决定"；06_执行与结算/现场记录。
- **注意**：现场变更直接用口令发起，不等摄取（D04 §10）。

## SC38 验收与结算

- **触发**："准备结算""整理验收资料"。
- **判别**：执行已结束。
- **路径**：
  1. S07·M4〔T2、T3〕约定与实际对照、交付证据、结算明细（引用报价编号）、差异说明（TP18）
  2. 【人】验收和结算确认
- **回写**：A04 价格状态"已结算"（由财务执行）；A01 结算金额、实际成本；主卡阶段"验收结算"。
