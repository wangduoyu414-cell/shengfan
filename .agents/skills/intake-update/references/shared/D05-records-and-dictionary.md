# D05 记录规范与业务词典

版本 v1.0 · 2026-11-09 · 通用规则层

适用于所有读写项目记录、共享资产和成果文件的任务。

---

## §1 基本要求

1. 每类事实只有一个权威位置（§2）。
2. 每条事实写明状态（§3）和来源（§4）。
3. 编号、文件名、版本按 §5、§6。
4. 方案、报价、执行用同一套服务模块编号（§7）。
5. 未知不填零（§11）。

---

## §2 权威位置

### §2.1 原则

每类事实只有一个权威位置。其他地方只引用（编号、链接、版本），不另存一份。发现两处不一致时以权威位置为准，并提出更正建议。

### §2.2 权威位置表

| 事实类型 | 权威位置 | 其他地方怎样引用 |
|---|---|---|
| 项目当前条件、方向、待确认事项、分工设置 | 项目主卡 `00_项目主卡.md` | 成果注明"依据主卡 YYYY-MM-DD 版" |
| 决定、变更、提交、确认、关键事件 | 项目日志 `00_项目日志.md` | 主卡显示最新结论，注明日志日期 |
| 原始文件 | 项目 `01_原始资料/`；证据原件在 A05 | 文件名＋页码 |
| 沟通原文 | 摄取系统的统一消息记录；项目 `02_沟通记录/` 中的摘要 | record_id |
| 项目清单、阶段、金额口径 | A01 项目总表 | 项目编号 |
| 资源身份与能力 | A03 资源档案 | R-编号 |
| 价格与报价条件 | A04 报价记录 | Q-编号 |
| 金额计算结果 | 项目 `03_资源与报价/` 中的成本测算表（按版本） | 成本表版本号 |
| 资质、业绩、标准响应段落 | A05 能力与证据库，或乐享（见 §2.3） | E-编号或乐享条目 |
| 客户组织、偏好、框架资格 | A06 客户档案 | C-编号 |
| 优秀方案、策划片段、风格卡、授权图片 | A07 方案素材库，或乐享（见 §2.3） | 文件路径或乐享条目 |

|---|---|---|---|---|---|---|---|
| （待建立：DQ15） | | | | | | | |

### §2.4 快照

从乐享或其他外部来源取得、放进任务包的内容，标注"快照｜来源｜条目名｜取得时间"。快照只读，随任务使用，不写回业务库，也不作为权威。

## §3 五套状态

五套状态各管各的对象，不合并成一列。AI 只能提出升级；过期和降级可以自动标出；每次升级都记来源。

### §3.1 信息状态（主卡中的每条事实）

| 值 | 含义 | 进入条件 |
|---|---|---|
| 待确认 | 有人说过或提出过，责任方尚未确认 | 摄取和录入的默认状态 |
| 已确认 | 责任方明确确认 | 书面确认、群内明确确认、合同或采购文件规定；由项目经理标记 |
| 推断 | AI 或员工的推测、建议 | 必须写明推断依据 |
| 作废 | 被新信息替代或撤回 | 保留原记录，注明被什么替代 |

- AI 只能写"待确认"或"推断"，可以建议升级为"已确认"，升级由项目经理执行。
- "大概""可能""考虑""争取"等说法一律是"待确认"。
- 同一事项出现新值时，旧值改为"作废"，不删除。

### §3.2 价格状态（报价记录）

| 值 | 含义 | 能否用于对外报价 |
|---|---|---|
| 参考价 | 公开平台或历史价格，不是供应商针对本项目的报价 | 否，只能用于估算 |
| 正式报价 | 供应商针对本项目的书面报价，有有效期 | 可以用于测算；对外报价前核对有效期 |
| 已核可用 | 已核实档期、数量和条件 | 可以 |
| 已锁定 | 已预订或签约 | 可以 |
| 已结算 | 实际发生并结算的价格 | 用于复盘和以后参考 |
| 已失效 | 过了有效期，或被撤回 | 否 |

- 过了有效期自动标"已失效"。
- 升级到"已核可用""已锁定"由资源采购执行；"已结算"由财务执行。

### §3.3 项目阶段（项目总表）

线索 → 需求确认 → 方案报价 → 已提交 → 已中选 → 执行准备 → 执行中 → 验收结算 → 已关闭

终止或中断：未中选、放弃、取消、暂停（暂停可以恢复到暂停前的阶段）。

- 框架入围记为"已中选"，但它是资格，不是订单。每次二次比选另立项目，"所属框架"填框架项目的编号。
- 阶段由项目经理变更，变更写入项目日志。

### §3.4 证据状态（能力与证据库）

已承诺（投标文件里写过）→ 已签约 → 已交付 → 已验收 → 已评价 → 已复购

另记：有效期、适用主体（我方，或合作方名称）、可否对外（内部、可对外、需授权）。

- 投标中只有"已交付"及以上的证据可以作为业绩；"已承诺"不能写成业绩。
- 合作方的证据只能以合作方名义使用，并按采购文件对第三方的要求处理。

### §3.5 成果版本状态（文件名与版本指针）

草稿 → 已发送 → 已确认；任何时候都可以变为"作废"。

- 每类成果对每个对象（对客、内部）只有一个当前有效版本，记在主卡的版本指针里。

## §6 文件命名与版本

### §6.1 成果文件

`{项目编号}_{成果类型}_{对客|内部}_V{n}_{版本状态}_{YYYYMMDD}.{扩展名}`

- 成果类型：方案、PPT、报价单、标书、执行手册、通知、文案、周报、复盘、视觉。
- 例：`2026-018_方案_对客_V3_已发送_20261112.pptx`
- 内容稿（Markdown）与排版文件同名，扩展名不同。

### §6.2 过程文件

| 文件 | 位置 | 命名 |
|---|---|---|
| 交接卡 | `_任务/` | `交接卡_{YYYYMMDD}_{序号}.md` |
| 任务包 | `_任务/` | `任务包_{YYYYMMDD}_{序号}/` |
| 更新建议单 | `_任务/` | `更新建议_{YYYYMMDD}_{序号}.md` |
| 变更影响单 | `_任务/` | `{变更编号}_变更影响.md` |
| 成本测算表 | `03_资源与报价/` | `{项目编号}_成本测算_V{n}_{YYYYMMDD}.xlsx` |
| 原始资料 | `01_原始资料/` | `{YYYY-MM-DD}_{原文件名}` |
| AI 图片 | `04_策划与设计/视觉/` | `{项目编号}_{用途}_{序号}_示意.{扩展名}`，同名 .md 记录平台与提示词 |
| 沟通摘要 | `02_沟通记录/` | `{YYYY-MM-DD}_{群简称}.md`（D04） |

### §6.3 版本

- 只增不覆盖；新版本号加一。
- 作废的版本移入同目录的 `_旧版/`。
- 版本状态变化时改文件名，并提出更新主卡版本指针的建议。

## §10 口径

- 日期写 YYYY-MM-DD；时间写 HH:MM（北京时间）。
- 金额以元为单位，写明含税或不含税，保留两位小数。
- 人数写明"计划人数""确认人数"或"实到人数"，不混用。
- 天数与间夜分开写：三天两晚 = 3 天、每人 2 晚。

---

## §11 未知、不适用与零

- 未知：留空，或写"未知"。
- 不适用：写"不适用"。
- 零：只在确实为零时写 0。
- 不得用 0 代替未知。

---

## §12 扩展字段

模板里的"扩展字段"用于暂时没有正式位置的信息。同类信息累计出现三次，提交扩展登记（RG01）。
