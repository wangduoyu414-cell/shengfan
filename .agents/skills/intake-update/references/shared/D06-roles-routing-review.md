# D06 分工、路由与复核规则

版本 v1.0 · 2026-11-09 · 通用规则层

---

## §1 执行层级

| 层级 | 判定条件（满足任一） | 默认执行者 |
|---|---|---|
| T1 判断与创造 | 输入含糊或冲突；需要在多个可行方案中取舍；需要创意、专业判断或策略；结果影响方向、金额或风险；关键视觉；设计 Skill、模板或工具 | GPT |
| T2 规则化生产 | 方向已定，有模板或明确简报；按规则抽取、整理、填表；中文成文；批量处理；归档命名 | 主执行平台（WorkBuddy 或豆包） |
| T3 确定性处理 | 结果可以计算出来，或可以按规则核对 | 表格公式、脚本 |
| T4 决定与承诺 | 对外、不可逆；涉及金额、合同、安全；状态升级 | 人 |

---

## §2 平台身份与默认分工

### §2.1 平台身份声明

每个平台的加载说明里有一段平台身份声明（方法库 `adapters/*/platform-identity.md`），写明：当前平台、默认层级、是否主执行平台、能否直接读写业务库、是否已连接乐享、可处理的数据级别。任务开始时先读这段声明。读不到时按 §2.2 的默认值处理，并在交接卡里注明。

### §2.2 默认分工

| 平台 | 默认层级 | 说明 |
|---|---|---|
| GPT | T1 | 也负责关键视觉、Skill 与工具的设计 |
| WorkBuddy | T2 | 默认主执行平台【默认：DQ02】 |
| 豆包 | T2 | 默认负责文案类成果，作为第二执行平台 |
| 表格、脚本 | T3 | |
| 人 | T4 | |

项目可以在主卡的"分工设置"里改主执行平台和文案平台。

## §3 路由

### §3.1 每个任务的路由顺序

1. **认项目**：从说法、文件名、群名中找项目编号。找不到且不是新建项目时，问一句"是哪个项目？"
2. **认场景**：查 project-hub 的场景路由表，匹配触发和判别要点。匹配到多个时，按路由表的判别规则区分；仍不能区分时问一句。
3. **读场景卡**：按卡中的路径执行；每一步用哪个 Skill 的哪个模式，由场景卡指定。
4. **每一步执行前做两项检查**：层级检查（§3.2）、数据检查（D07 §4）。
5. **收尾**：通用复核清单（§10）→ 按命名保存 → 回写建议 → 交接卡（§8）。

### §3.2 层级检查

| 本平台默认层级 | 步骤层级 | 做法 |
|---|---|---|
| 相同 | — | 在本平台执行 |
| T2 | T1 | 生成任务包交给 GPT（§9）；GPT 不可用或资料不允许进入 GPT 时，降级执行（§4.3） |
| T1 | T2 | 可以在本平台完成；批量或排版工作建议交回执行层 |
| 任意 | T3 | 用表格或脚本；不能运行时，按 Skill 给出的手工步骤 |
| 任意 | T4 | 准备材料，写明需要谁确认，停下等人决定 |

### §3.3 正式文件的写入

正式文件（方案、PPT、标书、报价单、执行手册）只由主卡登记的主责平台写入正式位置。其他平台的产出作为"输入"放在 `_任务/`，由主责平台合并（§5）。

### §3.4 外部知识检索

需要公司资料、历史案例、资质证据等时：

1. 查 D05 §2.2、§2.3，确定权威位置。
2. 权威位置在业务库：直接读取。
3. 权威位置在乐享，且本平台已连接：用检索工具（关键词或语义）找到条目，用读取工具取正文。
4. 本平台未连接乐享：在交接卡"需要的资料"中列出检索词，由已连接的平台补快照（D05 §2.4）。
5. 引用按 D05 §4 标注。检索不到时如实写"未检索到"，不编造。

## §4 升级、降级与降级执行

### §4.1 升级到 T1（满足任一）

1. 资料之间有冲突，并且影响方案、报价或承诺；
2. 需要在多个可行方案之间取舍，或客户诉求含糊；
3. 重大变更：总价变化 ≥ 5%；人数变化 ≥ 10%；日期、地点或主要资源变化；增减服务模块；涉及安全【阈值默认：DQ05】；
4. 新类型任务，没有模板或先例；
5. 同一成果自检两次仍不通过；
6. 对外关键成果的终审（§6）。

### §4.2 降级到 T2

方向和结构已定，后续是按模板成文、出变体、排版、归档或批量重复。之后 T1 只抽检或终审。

### §4.3 降级执行

GPT 不可用，或资料不允许进入 GPT 时，T1 步骤可以在执行层运行：

- 成果第一行写"【降级执行：未经 T1 审查】"；
- 在主卡待确认中加一条"降级结果待审"；
- 由负责人决定采用、补审或重做。

## §5 正式文件主责

每类正式文件在一个项目里只有一个主责平台和一个负责人，登记在主卡"分工设置"中。其他平台只提供方向、视觉、文案片段、审查意见，不产出平行的"最终版"。

---

## §6 复核分级

| 成果 | 自检 | 一致性检查 | T1 审查 | 人工审批 |
|---|---|---|---|---|
| 内部工作稿 | 必做 | — | — | — |
| 对客文案、通知 | 必做 | 人数、日期、地点 | — | 项目经理 |
| 对客方案、PPT | 必做 | 必做 | 首版和重大修改 | 项目经理 |
| 报价单 | 必做 | 必做 | 有取舍或异常时 | 负责人或财务 |
| 投标文件 | 必做 | 必做，含废标项 | 终审 | 商务负责人和负责人 |
| 执行手册 | 必做 | 必做 | 涉及安全或重大调整时 | 项目经理 |
| 变更确认 | — | 必做 | 重大变更 | 项目经理或负责人 |

审批人【默认：DQ06】。

## §7 人工关口

AI 可以准备、建议、起草、检查、提醒。以下动作必须由人完成或确认：

1. 是否立项跟进
2. 是否投标或接单
3. 方向选择
4. 供应商选择
5. 对外报价
6. 提交标书、发送任何对外文件
7. 确认客户变更
8. 签约
9. 预订和付款
10. 现场重大调整
11. 验收与结算确认
12. 任何状态升级（D05 §3）
13. 案例和素材能否对外使用
14. 在乐享中发布内容（D07 §5）

遇到以上动作时：准备好材料和建议，写明"需要 ×× 确认"，停止该步骤。

## §8 交接卡

每次任务结束都写一张（模板 TP03），放在 `_任务/`。

| 字段 | 内容 |
|---|---|
| 项目 | 编号与名称 |
| 场景 | SC 编号；设计外情况写"设计外" |
| 本次任务 | 一句话 |
| 执行平台与层级 | 例：WorkBuddy · T2；是否降级执行 |
| Skill 与版本 | 例：sourcing-costing v1.0 |
| 依据 | 主卡版本、文件、报价编号、乐享条目 |
| 已确认 | 本次用到的已确认事实 |
| 待确认 | 问题、向谁确认、截止时间 |
| 本次产出 | 文件名、位置、版本状态 |
| 回写建议 | 建议写入主卡、日志、资产的内容（等人确认） |
| 限制 | 资料的数据级别、处理方式、红线 |
| 下一步 | 场景中的下一步、负责人、时间 |
| 需要的资料 | 本平台取不到的资料（例如乐享快照） |

## §9 任务包

### §9.1 何时生成

- 步骤层级不是本平台的默认层级；
- 本平台无法访问所需资料；
- 需要由人把任务带到另一个平台。

### §9.2 内容

1. 交接卡（必有）；
2. 所用 Skill 的指令版（方法库 `adapters/generated/`）；
3. 必要资料：主卡或摘录、相关文件、乐享快照。每份资料先按 D07 §4 判定能否交给目标平台，不能的先脱敏或删除；
4. 产出要求：文件名、格式、保存位置、需要回写的内容。

### §9.3 形式

放在 `_任务/任务包_{YYYYMMDD}_{序号}/` 文件夹，附一份"任务包说明.md"：任务一句话、目标平台、资料清单及级别、截止时间。

### §9.4 回收

目标平台的产出按命名规则存回项目工作区。不能直接写入时由发起人保存，并在交接卡中登记。

## §10 通用复核清单（每个成果交付前）

1. **范围**：是否完成了本次要求的全部产出？
2. **依据**：每个关键事实是否有来源（D05 §4）？推断是否标明？
3. **状态**：有没有把待确认写成已确认？把参考价当成报价？把投标承诺当成业绩？
4. **数字**：人数、日期、天数、间夜、金额是否与主卡和成本表一致？金额是否来自成本表？
5. **一致**：同一事实在本成果内是否前后一致？与其他当前有效文件是否一致？
6. **承诺**：有没有未经确认的对外承诺（价格、档期、资源、效果）？
7. **数据**：有没有对象不应看到的内容（内部成本、个人信息、其他客户的信息）？
8. **格式**：文件名、版本状态、保存位置是否符合 D05 §6？
9. **关口**：是否需要人工确认？是否写明了需要谁确认？
10. **交接**：是否写了交接卡和回写建议？

## §11 平台差异与替代

| 需要的能力 | 本平台没有时 |
|---|---|
| 写入业务库 | 输出完整内容，注明文件名和保存位置，由人或主执行平台保存 |
| 读取业务库 | 请发起人提供任务包，或在交接卡里列出需要的文件 |
| 连接乐享 | 在交接卡"需要的资料"中列出检索词，由已连接的平台补快照 |
| 运行脚本 | 用表格模板或 Skill 中的手工步骤 |
| 读写 XLSX | 用 Markdown 表格输出，由人粘贴进表格 |
| 生成 PPTX、DOCX | 输出内容稿（Markdown），由排版平台套用模板 |
| 生成或编辑图片 | 输出提示词和风格卡，由有能力的平台生成 |
| 原生技能 | 使用指令版（`adapters/generated/`） |

所有替代都在交接卡里写明。

---

## §12 设计外情况

遇到场景路由表中没有的情况：按最接近的场景处理，在项目日志里标"设计外"，在交接卡中注明。同类情况出现三次，或负责人认为重要时，提交扩展登记（RG01）。
