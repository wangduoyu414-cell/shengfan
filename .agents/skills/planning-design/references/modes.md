# 策划与方案设计：模式

版本 v1.0 · 方法层 · 属于 planning-design（S03）

全部为 T1。在执行层降级执行时，按 D06 §4.3 标注。

---

## M1 方向生成

适用：SC13–SC16 第 1 步。

1. **定目标**：写出主目标（D05 §8.3）和可以观察的成功标准（例如"参会者能说出三个合作方向""学员结业考核通过率"）。
2. **列约束**：预算、日期、人数、地点、硬性要求、评分要点（招投标）。
3. **找参照**：A07 中同产品族、同客户类型的方案；A06 客户偏好。参照只用来借鉴，不照搬。
4. **生成 2–3 个方向**，至少在两个维度上实质不同：
   - 核心体验（例如：高效会务／文化体验／团队共创）
   - 内容深度（轻松／专业）
   - 节奏（紧凑／舒缓）
   - 资源组合（服务模块的组合方式）
   - 预算结构（钱主要花在哪里）
5. **每个方向写清**：一句话主张、核心体验、关键环节、资源（模块）、预算压力、主要风险、适合条件。
6. **对比与推荐**：填 TP08 第一部分，写出推荐和理由；明确"需要负责人选择"。

## M2 方案结构

适用：选定方向之后。

1. **模块组合**：按 D05 §7 列出用到的服务模块和每个模块的内容。
2. **日程**：行程、议程或课表，精确到时段；检查交通时长、场地容量、时间衔接、用餐和休息。
3. **体验设计要点**：开场、高潮、收尾，参与者的感受。
4. **资源需求清单**：按模块写需求、数量、日期、规格，交 sourcing-costing M1。
5. **风险与应急**：天气、交通、人员、设备、安全。
6. 填 TP08 第二部分。

## M3 风格与主视觉

适用：SC18；SC13–SC16 需要视觉时。

1. 没有风格卡时，先按 TP09 做风格卡：主题关键词、色彩值、构图、字体、画面元素、禁用元素、参考图。品牌要素按 D10 §1（未提供时用中性风格）。
2. 生成主视觉、封面、概念图；或按要求编辑图片（局部修改、合成、统一风格）。
3. 每张图标"创意示意"；保存为 `{项目编号}_{用途}_{序号}_示意.{扩展名}`，同名 .md 记录平台、提示词、用途。
4. 带中文字的画面按 D10 §6 处理。
5. 列出需要人确认的视觉。

## M4 方案审查

适用：SC26 第 2 步（首版和重大修改）；SC27 终审（与需求矩阵一起看）。

逐项检查，输出"必须改"和"建议改"两类意见：

| 检查项 | 看什么 |
|---|---|
| 目标契合 | 每个主要环节是否服务于主目标 |
| 可执行 | 交通时长、场地容量、时间冲突、季节与天气 |
| 资源成立 | 写进方案的资源是否有报价或已核可用 |
| 成本受控 | 是否与成本测算版本一致；有没有隐含的额外费用 |
| 差异化 | 与同类方案相比的亮点 |
| 风险 | 安全、合规（金融客户的营销合规）、未成年人 |
| 承诺适度 | 有没有未经确认的效果、档期、价格承诺 |
| 评分覆盖 | 招投标项目：每个评分项都有对应内容 |

## M5 含糊反馈

适用：SC17。

1. 把意见拆成可以操作的维度：

| 客户说法 | 可能指的是 |
|---|---|
| 更高级 | 空间与场地档次、服务密度、稀缺体验、仪式感、视觉质感、嘉宾层级 |
| 更有特色 | 地方文化、独特场地、互动形式、主题包装 |
| 更轻松 | 节奏、自由时间、强度、正式程度 |
| 更有内容 | 讲师或嘉宾、学习环节、成果产出 |

2. 在预算和日期约束内，给出 2–3 个调整方案；每个方案标明是否需要更换或新增资源（需要时交 sourcing-costing M3、M4）。
3. 建议先向客户确认是哪一种理解（可以给出问法），再改方案。
