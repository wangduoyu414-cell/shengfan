# 乐享 MCP 连接配置示例

版本 v1.0 · 不含任何真实令牌 · 依据 D12

把 `{乐享code}` 换成企业的乐享 code（登录后在 https://lexiangla.com/mcp 获取）。令牌只填在平台的连接配置里，不写进方法库、任务包或聊天（D07 §6）。

---

## 1 接入地址

| 用途 | 地址 |
|---|---|
| 全部工具 | `https://mcp.lexiang-app.com/mcp?company_from={乐享code}` |
| 元工具（动态发现） | `https://mcp.lexiang-app.com/mcp?company_from={乐享code}&preset=meta`（公开文档未记载，登录后确认） |
| 完整知识库工具 | `https://mcp.lexiang-app.com/mcp?company_from={乐享code}&preset=knowledge` |
| 令牌方式 | 在上述地址后追加 `&access_token={令牌}`（令牌来自乐享 MCP 页面的"会话管理"） |

建议：执行层平台用 `preset=knowledge` 或不填；只做检索的场景，也可以只给检索类工具（以登录后列出的工具为准）。

## 2 WorkBuddy（mcp.json）

OAuth 方式（点击 Connect 授权）：

```json
{
  "mcpServers": {
    "lexiang": {
      "type": "http",
      "url": "https://mcp.lexiang-app.com/mcp?company_from={乐享code}&preset=knowledge"
    }
  }
}
```

请求头方式（不支持 OAuth 时）：

```json
{
  "mcpServers": {
    "lexiang": {
      "type": "http",
      "url": "https://mcp.lexiang-app.com/mcp?company_from={乐享code}&preset=knowledge",
      "headers": { "Authorization": "Bearer {令牌}" }
    }
  }
}
```

## 3 Codex（config.toml）

```toml
[mcp_servers.lexiang]
url = "https://mcp.lexiang-app.com/mcp?company_from={乐享code}&preset=knowledge"
```

认证方式以当前 Codex 版本为准（OAuth 登录，或在地址中追加 access_token）。

## 4 ChatGPT

设置 → 连接器（或应用）→ 开发者模式 → 新建连接器：URL 填 `https://mcp.lexiang-app.com/mcp?company_from={乐享code}`，认证选 OAuth。建议使用只开放 L1、L2 知识库的账号（DQ17）。

## 5 豆包工作

插件·技能·伙伴 → 连接器 → 新建自定义连接器：传输类型 HTTP；服务器 URL 填 `https://mcp.lexiang-app.com/mcp?company_from={乐享code}&preset=knowledge&access_token={令牌}`。

## 6 只支持本地命令的客户端

用 `mcp-remote` 桥接（需要 Node.js）：

```json
{
  "mcpServers": {
    "lexiang": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "https://mcp.lexiang-app.com/mcp?company_from={乐享code}"]
    }
  }
}
```

## 7 连接后

执行 D12 §8 的验证清单；只读部分可以用 `tools/lexiang_probe.py`。结果写入 `../兼容矩阵.md` 第 4 节。
