# 豆包接入说明（豆包、豆包工作）

版本 v1.0 · 默认层级 T2 · 默认负责文案类成果，第二执行平台

---

## 1 加载方式

没有查到豆包原生导入 SKILL.md 技能包的官方说明，先用以下两种方式；实测支持后改为导入 `dist/` 下的 zip，并更新兼容矩阵。

### 1.1 智能体或项目（常驻）

- **指令**：`platform-identity.md` ＋ `../generated/project-hub.md`。
- **知识文件**：`../generated/shared-rules.md`、`../generated/scenarios.md`、`../generated/deliverable-production.md`、`../generated/intake-update.md`，以及需要的其他 Skill 指令版。
- 指令长度超过平台上限时，指令只放平台身份声明和 project-hub 指令版的第 1–9 节，其余作为知识文件。

### 1.2 任务包（一次性）

把任务包文件夹中的交接卡、Skill 指令版和资料一起交给豆包，按任务包说明执行。

## 2 业务库

豆包通常不能直接读写本地业务库：通过任务包取得资料；产出由发起人或主执行平台按命名规则保存。豆包工作可以连接的文档空间，按 DQ01 的结果另行配置。

## 3 默认负责的成果

对客文案与通知（deliverable-production M5）：邀请函、行前通知、主持串词、宣传稿、客户沟通回复草稿；以及作为第二执行平台承担的 T2 任务。

## 4 乐享【待实测】

豆包工作：插件·技能·伙伴 → 连接器 → 新建自定义连接器，传输类型 HTTP，填写乐享接入地址。没有 OAuth 时使用 access_token 参数（令牌只填在连接器配置里，不写进指令或知识文件）。配置示例见 `../lexiang/连接配置示例.md`。

## 5 手机端

执行人员在现场可以用手机端豆包记录异常、起草通知（SC37）；需要写入业务库的内容，回到主执行平台保存。
