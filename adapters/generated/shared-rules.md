# 通用规则索引

版本 v1.0 · 2026-11-09 · 通用规则层

本目录是**通用规则层**的唯一来源：对所有项目、所有场景、所有平台都成立的规则和策略。

- 具体场景怎样走（路由路径），不写在这里，写在主 Skill「项目总控」的场景卡里。
- 某个 Skill 内部怎样做，写在该 Skill 的模式文件里。
- 场景卡和模式文件只写本场景、本模式特有的内容；涉及通用规则时引用编号（如"按 D06 §4.1"），不复制原文。

# D05 记录规范与业务词典

版本 v1.0 · 2026-11-09 · 通用规则层

适用于所有读写项目记录、共享资产和成果文件的任务。

---

## §1 基本要求

1. 每类事实只有一个权威位置（§2）。
2. 每条事实写明状态（§3）和来源（§4）。
3. 编号、文件名、版本按 §5、§6。
4. 方案、报价、执行用同一套服务模块编号（§7）。
5. 未知不填零（§11）。

---

## §2 权威位置

### §2.1 原则

每类事实只有一个权威位置。其他地方只引用（编号、链接、版本），不另存一份。发现两处不一致时以权威位置为准，并提出更正建议。

### §2.2 权威位置表

| 事实类型 | 权威位置 | 其他地方怎样引用 |

| 原始文件 | 项目 `01_原始资料/`；证据原件在 A05 | 文件名＋页码 |
| 沟通原文 | 摄取系统的统一消息记录；项目 `02_沟通记录/` 中的摘要 | record_id |

## §3 五套状态

五套状态各管各的对象，不合并成一列。AI 只能提出升级；过期和降级可以自动标出；每次升级都记来源。

### §3.1 信息状态（主卡中的每条事实）

| 值 | 含义 | 进入条件 |
|---|---|---|
| 待确认 | 有人说过或提出过，责任方尚未确认 | 摄取和录入的默认状态 |
| 已确认 | 责任方明确确认 | 书面确认、群内明确确认、合同或采购文件规定；由项目经理标记 |
| 推断 | AI 或员工的推测、建议 | 必须写明推断依据 |
| 作废 | 被新信息替代或撤回 | 保留原记录，注明被什么替代 |

- AI 只能写"待确认"或"推断"，可以建议升级为"已确认"，升级由项目经理执行。
- "大概""可能""考虑""争取"等说法一律是"待确认"。
- 同一事项出现新值时，旧值改为"作废"，不删除。

### §3.2 价格状态（报价记录）

| 值 | 含义 | 能否用于对外报价 |
|---|---|---|
| 参考价 | 公开平台或历史价格，不是供应商针对本项目的报价 | 否，只能用于估算 |
| 正式报价 | 供应商针对本项目的书面报价，有有效期 | 可以用于测算；对外报价前核对有效期 |
| 已核可用 | 已核实档期、数量和条件 | 可以 |
| 已锁定 | 已预订或签约 | 可以 |
| 已结算 | 实际发生并结算的价格 | 用于复盘和以后参考 |
| 已失效 | 过了有效期，或被撤回 | 否 |

- 过了有效期自动标"已失效"。
- 升级到"已核可用""已锁定"由资源采购执行；"已结算"由财务执行。

### §3.3 项目阶段（项目总表）

线索 → 需求确认 → 方案报价 → 已提交 → 已中选 → 执行准备 → 执行中 → 验收结算 → 已关闭

终止或中断：未中选、放弃、取消、暂停（暂停可以恢复到暂停前的阶段）。

- 框架入围记为"已中选"，但它是资格，不是订单。每次二次比选另立项目，"所属框架"填框架项目的编号。
- 阶段由项目经理变更，变更写入项目日志。

### §3.4 证据状态（能力与证据库）

已承诺（投标文件里写过）→ 已签约 → 已交付 → 已验收 → 已评价 → 已复购

另记：有效期、适用主体（我方，或合作方名称）、可否对外（内部、可对外、需授权）。

- 投标中只有"已交付"及以上的证据可以作为业绩；"已承诺"不能写成业绩。
- 合作方的证据只能以合作方名义使用，并按采购文件对第三方的要求处理。

### §3.5 成果版本状态（文件名与版本指针）

草稿 → 已发送 → 已确认；任何时候都可以变为"作废"。

- 每类成果对每个对象（对客、内部）只有一个当前有效版本，记在主卡的版本指针里。

## §10 口径

- 天数与间夜分开写：三天两晚 = 3 天、每人 2 晚。

- 不得用 0 代替未知。

# D06 分工、路由与复核规则

版本 v1.0 · 2026-11-09 · 通用规则层

---

## §1 执行层级

| 层级 | 判定条件（满足任一） | 默认执行者 |
|---|---|---|
| T1 判断与创造 | 输入含糊或冲突；需要在多个可行方案中取舍；需要创意、专业判断或策略；结果影响方向、金额或风险；关键视觉；设计 Skill、模板或工具 | GPT |
| T2 规则化生产 | 方向已定，有模板或明确简报；按规则抽取、整理、填表；中文成文；批量处理；归档命名 | 主执行平台（WorkBuddy 或豆包） |
| T3 确定性处理 | 结果可以计算出来，或可以按规则核对 | 表格公式、脚本 |
| T4 决定与承诺 | 对外、不可逆；涉及金额、合同、安全；状态升级 | 人 |

---

## §2 平台身份与默认分工

### §2.1 平台身份声明

每个平台的加载说明里有一段平台身份声明（方法库 `adapters/*/platform-identity.md`），写明：当前平台、默认层级、是否主执行平台、能否直接读写业务库、是否已连接乐享、可处理的数据级别。任务开始时先读这段声明。读不到时按 §2.2 的默认值处理，并在交接卡里注明。

### §2.2 默认分工

| 平台 | 默认层级 | 说明 |
|---|---|---|
| GPT | T1 | 也负责关键视觉、Skill 与工具的设计 |
| WorkBuddy | T2 | 默认主执行平台【默认：DQ02】 |
| 豆包 | T2 | 默认负责文案类成果，作为第二执行平台 |
| 表格、脚本 | T3 | |
| 人 | T4 | |

项目可以在主卡的"分工设置"里改主执行平台和文案平台。

---

## §3 路由

### §3.1 每个任务的路由顺序

1. **认项目**：从说法、文件名、群名中找项目编号。找不到且不是新建项目时，问一句"是哪个项目？"
2. **认场景**：查 project-hub 的场景路由表，匹配触发和判别要点。匹配到多个时，按路由表的判别规则区分；仍不能区分时问一句。
3. **读场景卡**：按卡中的路径执行；每一步用哪个 Skill 的哪个模式，由场景卡指定。
4. **每一步执行前做两项检查**：层级检查（§3.2）、数据检查（D07 §4）。
5. **收尾**：通用复核清单（§10）→ 按命名保存 → 回写建议 → 交接卡（§8）。

### §3.2 层级检查

| 本平台默认层级 | 步骤层级 | 做法 |
|---|---|---|
| 相同 | — | 在本平台执行 |
| T2 | T1 | 生成任务包交给 GPT（§9）；GPT 不可用或资料不允许进入 GPT 时，降级执行（§4.3） |
| T1 | T2 | 可以在本平台完成；批量或排版工作建议交回执行层 |
| 任意 | T3 | 用表格或脚本；不能运行时，按 Skill 给出的手工步骤 |
| 任意 | T4 | 准备材料，写明需要谁确认，停下等人决定 |

### §3.3 正式文件的写入

正式文件（方案、PPT、标书、报价单、执行手册）只由主卡登记的主责平台写入正式位置。其他平台的产出作为"输入"放在 `_任务/`，由主责平台合并（§5）。

### §3.4 外部知识检索

需要公司资料、历史案例、资质证据等时：

1. 查 D05 §2.2、§2.3，确定权威位置。
2. 权威位置在业务库：直接读取。
3. 权威位置在乐享，且本平台已连接：用检索工具（关键词或语义）找到条目，用读取工具取正文。
4. 本平台未连接乐享：在交接卡"需要的资料"中列出检索词，由已连接的平台补快照（D05 §2.4）。
5. 引用按 D05 §4 标注。检索不到时如实写"未检索到"，不编造。

## §4 升级、降级与降级执行

### §4.1 升级到 T1（满足任一）

1. 资料之间有冲突，并且影响方案、报价或承诺；
2. 需要在多个可行方案之间取舍，或客户诉求含糊；
3. 重大变更：总价变化 ≥ 5%；人数变化 ≥ 10%；日期、地点或主要资源变化；增减服务模块；涉及安全【阈值默认：DQ05】；
4. 新类型任务，没有模板或先例；
5. 同一成果自检两次仍不通过；
6. 对外关键成果的终审（§6）。

### §4.2 降级到 T2

方向和结构已定，后续是按模板成文、出变体、排版、归档或批量重复。之后 T1 只抽检或终审。

### §4.3 降级执行

GPT 不可用，或资料不允许进入 GPT 时，T1 步骤可以在执行层运行：

- 成果第一行写"【降级执行：未经 T1 审查】"；
- 在主卡待确认中加一条"降级结果待审"；
- 由负责人决定采用、补审或重做。

## §5 正式文件主责

每类正式文件在一个项目里只有一个主责平台和一个负责人，登记在主卡"分工设置"中。其他平台只提供方向、视觉、文案片段、审查意见，不产出平行的"最终版"。

| 对客方案、PPT | 必做 | 必做 | 首版和重大修改 | 项目经理 |

AI 可以准备、建议、起草、检查、提醒。以下动作必须由人完成或确认：

2. 是否投标或接单

4. 供应商选择

## §9 任务包

### §9.1 何时生成

- 步骤层级不是本平台的默认层级；
- 本平台无法访问所需资料；
- 需要由人把任务带到另一个平台。

### §9.2 内容

1. 交接卡（必有）；
2. 所用 Skill 的指令版（方法库 `adapters/generated/`）；
3. 必要资料：主卡或摘录、相关文件、乐享快照。每份资料先按 D07 §4 判定能否交给目标平台，不能的先脱敏或删除；
4. 产出要求：文件名、格式、保存位置、需要回写的内容。

### §9.3 形式

放在 `_任务/任务包_{YYYYMMDD}_{序号}/` 文件夹，附一份"任务包说明.md"：任务一句话、目标平台、资料清单及级别、截止时间。

### §9.4 回收

目标平台的产出按命名规则存回项目工作区。不能直接写入时由发起人保存，并在交接卡中登记。

## §10 通用复核清单（每个成果交付前）

1. **范围**：是否完成了本次要求的全部产出？
2. **依据**：每个关键事实是否有来源（D05 §4）？推断是否标明？
3. **状态**：有没有把待确认写成已确认？把参考价当成报价？把投标承诺当成业绩？
4. **数字**：人数、日期、天数、间夜、金额是否与主卡和成本表一致？金额是否来自成本表？
5. **一致**：同一事实在本成果内是否前后一致？与其他当前有效文件是否一致？
6. **承诺**：有没有未经确认的对外承诺（价格、档期、资源、效果）？
7. **数据**：有没有对象不应看到的内容（内部成本、个人信息、其他客户的信息）？
8. **格式**：文件名、版本状态、保存位置是否符合 D05 §6？
9. **关口**：是否需要人工确认？是否写明了需要谁确认？
10. **交接**：是否写了交接卡和回写建议？

# D07 数据分级与平台准入

版本 v1.0 · 2026-11-09 · 通用规则层 · 准入默认值待负责人确认（DQ04、DQ17）

---

## §1 四个级别

| 级别 | 定义 | 例子 |
|---|---|---|
| L1 公开 | 已公开或可以公开 | 公开招标公告和采购文件、公开网页、公开价格、公司对外宣传资料 |
| L2 内部 | 公司内部使用，泄露影响有限 | 方案草稿、内部策略、不含供应商身份的成本结构、标准响应段落、模板 |
| L3 保密 | 客户或商业上的保密信息 | 非公开采购文件、客户内部资料与组织信息、供应商报价与底价、合同、投标报价 |
| L4 个人敏感 | 能识别具体个人的信息，以及敏感个人信息 | 参会和出行名单、证件号、手机号、银行卡号、健康信息、未成年人信息、能识别人脸的照片 |

一份资料按其中最高级别的内容定级。

---

## §2 准入矩阵【默认】

| 级别 | GPT | WorkBuddy | 豆包 | 乐享 | 表格与本地工具 |
|---|---|---|---|---|---|
| L1 | 可以 | 可以 | 可以 | 可以 | 可以 |
| L2 | 可以（企业账号） | 可以 | 可以 | 可以 | 可以 |
| L3 | 只给脱敏版本 | 可以（企业账号，最少必要） | 可以（企业账号，最少必要） | 放在受限知识库 | 可以 |
| L4 | 不可以 | 只限负责人指定的一个平台，用编号代替姓名 | 同左 | 受限知识库，按需授权 | 可以（首选） |

客户合同或采购文件中的保密条款优先于本表。

---

## §3 脱敏方法

| 内容 | 做法 |
|---|---|
| 客户名称 | 换成代号，例如"某股份制银行 A 分行" |
| 联系人 | 换成角色，例如"客户采购负责人" |
| 金额 | 换成区间或比例，例如"预算 40–50 万""比上次高约 8%" |
| 供应商 | 换成代号（酒店 A、B、C），保留规格和条件 |
| 名单 | 换成数量和结构，例如"52 人，其中领导 6 人" |
| 证件号、手机号 | 删除 |
| 文件 | 只摘录需要的段落 |

脱敏后的资料标"脱敏版"，不写回业务库。

---

## §4 判定流程（每次把资料交给任何平台之前）

1. 确认目标平台。
2. 给每份资料定级：摄取时已有级别的沿用，没有的按 §1 判定。
3. 对照 §2：可以 → 交付；需要脱敏 → 按 §3 处理后交付；不可以 → 不交，改用准入平台，或交给人处理。
4. 在交接卡"限制"中写明资料级别和处理方式。

---

## §5 乐享

- 乐享知识库按 L1–L4 标注级别，登记在 D05 §2.3 的映射表里。
- 连接乐享的账号只开放该平台准入级别以内的知识库；GPT 的连接只开放 L1、L2【默认：DQ17】。
- AI 在乐享中默认只读。写入只在"AI 产出区"知识库进行，并进入乐享的审核流程【默认：DQ16】；发布由人完成。
- AI 不调用删除类的块编辑工具（`block_delete_block`、`block_delete_block_children`）。
- 更新已有文档时必须是"在原文档上更新"，不另建新文档。

---

## §6 密钥与令牌

乐享 access_token、平台 API Key 等都是密钥：

- 不写进方法库、任务包、聊天记录或任何文档；
- 只保存在平台的连接配置或环境变量里；
- 每人使用自己的令牌；
- 人员离职或令牌泄露时立即作废。

---

## §7 记录

L3、L4 资料跨平台交付时，在交接卡中登记：资料、级别、目标平台、处理方式。

---

## §8 例外

确需超出 §2 的使用，由负责人书面批准，写入项目日志，注明范围和期限。

# D09 报价与成本口径

版本 v1.0 · 2026-11-09 · 通用规则层 · 公司参数待财务确认（DQ18）

---

## §1 原则

1. 金额只在成本测算表中计算（模板 `X01-cost-calculator.xlsx`，每个项目复制一份）；AI 不心算总价。
2. 测算用到的每个价格都引用报价编号，并保存当时的数值作为快照；报价变化后，测算表标"需重算"。
3. 未知费用列为"待查"，不填零。
4. 对外报价必须引用成本测算表的版本号。

---

## §2 计价方式

| 计价方式 | 计算 | 常见模块 | 注意 |
|---|---|---|---|
| 总价包干 | 固定总价 | M01、M06 | 写明包含范围 |
| 分项单价 | 单价 × 数量 | 所有 | 数量单位与报价一致 |
| 人均 | 单价 × 人数 | M04、M10、M15 | 写明按计划人数还是实到人数 |
| 人天 | 单价 × 人数 × 天数 | M02、M11 | 半天怎样计 |
| 课时 | 单价 × 课时 | M02 | 一个课时多长 |
| 间夜 | 单价 × 间数 × 晚数 | M03 | 单人或双人入住、加床 |
| 车·天 | 单价 × 车辆数 × 天数 | M05 | 超时、超公里、过路停车 |
| 场次 | 单价 × 场次 | M03、M06、M08 | 搭建撤场时间是否计费 |
| 面积 | 单价 × 平方米 | M07、M08 | 按实际尺寸 |
| 优惠率 | 基准价 ×（1 − 优惠率） | 框架订单 | 基准价从哪里来 |
| 预算上限内报价 | 不超过预算上限 | 招投标 | 上限是否含税 |
| 据实结算 | 按实际发生 | 框架订单 | 单价上限、需要的凭证 |

## §3 成本构成与易漏项

成本按服务模块列（D05 §7）。每次测算都核对以下容易漏的费用：

司机超时与食宿；过路停车费；导游或讲师差旅；设备运输与搬运；搭建撤场加时；场地加时；物料损耗与备份；工作人员差旅与食宿；保险；发票税点差；退改损失；管理成本；风险预备。

## §5 价格状态的使用

- 参考价只用于估算，测算表中标"参考价"；对外报价前必须换成正式报价或已核可用的价格。
- 正式报价必须在有效期内；距有效期 7 天以内时提示续期【默认】。
- 已锁定的价格发生变化（例如供应商涨价），走 change-review 的报价变化影响（M4）。

## §6 最低安全报价【参数待财务确认】

最低安全报价 =（已知成本 + 待查项估算 + 风险预备）÷（1 − 毛利底线）

| 参数 | 默认 | 说明 |
|---|---|---|
| 毛利底线 | ____%（待定） | 低于此值需要负责人批准 |
| 风险预备 | ____%（待定），或按项目逐项列明 | 应对现场变化、人数波动 |
| 待查项估算 | 按同类历史价格或参考价，标"估算" | |

测算表自动比较拟报价与最低安全报价；低于时标出，需要负责人批准。

- 每档列出总成本、拟报价、人均和毛利率。
