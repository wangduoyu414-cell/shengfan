## 1 使用方法

1. 先认项目（D06 §3.1）。
2. 用第 3 节的"典型说法或事件"和"判别要点"找到唯一的场景。
3. 匹配到多个时，按第 4 节的判别规则区分；仍不能区分时，只问一个问题（第 4 节给出了问法）。
4. 打开场景卡所在的文件，按路径执行。
5. 都不匹配时，按 SC46（设计外）处理。

## SC01 收到招标公告或采购文件

- **触发**：上传采购文件或招标公告；"这个标看一下"。
- **判别**：有正式采购文件，且不是框架内的二次比选（否则 SC02）。
- **前置**：采购文件完整（含附件、澄清）；是否扫描件（需要文字识别时先识别）。
- **路径**：
  1. S00·P1〔T2〕新建项目，入口类型"招投标"，原件存 01_原始资料 → 工作区、主卡初稿
  2. S02·M1〔T1 解读；T2 填表〕资格、评分、实质性条款、废标风险、截止时间、需求矩阵、澄清问题 → TP06
  3. S02·M6〔T2〕资格条件逐条对照 A05：有效期、主体、证据状态 → 资格缺口
  4. S02·M4〔T1〕参与判断要点与建议 → TP06 第 7 节
  5. 【人】负责人决定投不投；投 → 按主产品族转 SC13–SC16；不投 → 阶段"放弃"，转 SC40（简版）
- **回写**：A01 新增一行；主卡（截止时间、硬性要求、评分要点、待确认）；日志"决定：投标／放弃"。
- **分支**：澄清问题需要发出 → 列入待确认，由人决定是否发出；资格不满足且无法补证 → 建议放弃。
- **注意**：截止时间写进主卡"下一节点"，并列入周报。

## SC02 框架客户的二次比选或询价

- **触发**：框架客户群里出现新需求；上传比选或询价通知。
- **判别**：客户在 A06 有有效的框架资格，需求在框架范围内（否则 SC01）。
- **前置**：框架资格有效期；本次比选方式（价格优先还是综合评分）。
- **路径**：
  1. S00·P1〔T2〕新建项目，入口"框架内订单"，所属框架填框架项目编号；在 A08 把新项目加入该群的活跃项目 → 工作区、主卡初稿
  2. S02·M2〔T2；差异涉及评分、资格或新模块时 T1〕与最近 3 个同客户同类项目比对 → 差异表（TP06 快速模式附表）、复用清单
  3. S04·M2、M4〔T2、T3〕查 A04 同城同类的有效报价，过期的转 S04·M1 询价；复制测算表测算 → 成本测算 V1
  4. S05·M1、M4〔T2；差异部分 T1 审查〕以上次中选方案为底稿改写方案和报价单 → 方案 V1、报价单 V1
  5. S06·M3〔T3、T2〕一致性终检 → 检查结果
  6. 【人】负责人审批报价并发送
- **回写**：A01 新增一行（所属框架）；主卡；A04 新报价；日志"提交"。
- **分支**：没有可比的历史订单 → 第 2 步改用 S02·M1；客户要求新创意 → 第 3 步前插入 S03·M1 与【人：选方向】。
- **注意**：首版目标 48 小时内【默认】。

## SC03 直客提出新需求

- **触发**：客户在群里、电话里或会面时提出想法。
- **判别**：没有采购文件，需求含糊（有采购文件时按 SC01）。
- **前置**：沟通内容已摄取或已手工投递。
- **路径**：
  1. S01·M2〔T2〕整理这次沟通 → 更新建议单
  2. S00·P1〔T2〕新建项目，入口"直接委托" → 工作区、主卡初稿
  3. S02·M3〔T2；目标含糊时 T1〕按主产品族策划卡的"必问问题"对照已知和未知 → 澄清问题（不超过 8 个，按影响排序）
