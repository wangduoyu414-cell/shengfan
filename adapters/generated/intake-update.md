# 指令版：intake-update

> 用途：资料收录与项目更新。处理企业微信会话存档的沟通摘要、"更新项目"请求、收到的文件、会议纪要和录音转写、多项目群的消息归属；把新信息整理成带来源和状态的更新建议单，等项目经理确认后再写入主卡。

> 使用方法：作为项目或智能体的指令，或放进任务包。通用规则见 shared-rules.md；project-hub 的场景见 scenarios.md。

# 资料收录与项目更新（S01）

## 1 何时使用，何时不用

- **使用**：摄取批次到达（SC04）；"更新项目 018"（SC03 第 1 步）；收到文件（SC05）；手工投递纪要、录音、截图（SC06）；冲突（SC07）；待归属（SC08）；答疑文件归档（SC12 第 1 步）。
- **不用**：直接修改已确认事实（由人确认后写入）；生成对外成果（交 deliverable-production）；分析变更影响（交 change-review）。

- **必需**：新增的沟通摘要或文件；项目主卡。

- **缺主卡**：先走 project-hub P1 新建项目。
- **缺发言人身份**：按"未知"处理，在建议单中列出，建议补登 A08。

`02_沟通记录/` 摘要（格式见 D04 §9.2）；`01_原始资料/`；A08；A04（报价线索）；A06（客户线索）。模板：TP05 更新建议单、TP01、TP02、TP03。

## 6 验收

- 每条建议都有来源（record_id 或文件）。
- 摄取内容默认"待确认"；没有把"可能""考虑"写成已确认。
- 所有变更触发都列出了涉及的模块和是否重大。
- 冲突单列，没有自行选一个值。
- 没有直接修改主卡。
- L4 信息没有出现在建议单正文里（只写"名单文件（N 人），见原件"）。

常见失败：把客户的试探当成决定；漏掉群里图片或文件中的信息；重复处理已处理过的消息。

# 资料收录与项目更新：模式与规则

版本 v1.0 · 方法层 · 属于 intake-update（S01）

---

## M1 批次处理（摄取摘要）〔T2〕

适用：SC04。

1. 读主卡"沟通记录已处理到"，找到 02_沟通记录 中之后的内容。
2. 跳过已撤回的消息（标"[已撤回]"）和无业务内容的消息。
3. 对每条有业务内容的消息，按"分类规则"归入"需确认"或"仅记录"。
4. 对照主卡当前有效条件，按"变更触发规则"找出变化。
5. 按"冲突规则"找出冲突。
6. 发言人是供应商且内容涉及价格时，按"报价线索规则"处理。
7. 生成更新建议单（TP05）；没有新内容时，只建议更新处理位置。

## M2 按需更新（"更新项目 018"）〔T2〕

适用：SC03 第 1 步；人主动要求更新。

1. 如果摄取系统支持按需拉取，先拉取最新摘要（D04 §10）。
2. 其余同 M1。

## M3 文件收录〔T2〕

适用：SC05、SC12 第 1 步。

1. 确认所属项目（文件来源的群、文件名、内容）。
2. 定级（D07 §1）：名单、证件类为 L4；客户内部资料、报价、合同为 L3。
3. 按 D05 §6.2 命名，建议存入 `01_原始资料/`。
4. 提取要点：需求表 → 条件；报价单 → 报价线索；合同 → 转 SC34；答疑 → 转 SC12。
5. L4 文件不在建议单里展开内容，只写"名单文件（N 人），见原件"。

## M4 手工投递〔T2〕

适用：SC06。

1. 读投递的纪要、录音转写或截图（截图先识别文字）。
2. 按 D04 §4 的字段整理成统一格式，`source=manual`。
3. 存入 `02_沟通记录/{YYYY-MM-DD}_{会议或通话简称}.md`。
4. 其余同 M1。

## M5 归属判断〔T2〕

适用：SC08。

1. 列出该群的活跃项目（A08）。
2. 对每条待归属消息，按日期、地点、人数、项目名称、引用关系判断最可能的项目，写出理由。
3. 无法判断时，保持"待归属"，列出可能的项目。
4. 一条消息可以属于多个项目。

## 分类规则

| 类别 | 内容 | 是否需确认 |
|---|---|---|
| 条件变更 | 日期、人数、地点、预算、天数、服务内容、硬性要求的新值或变化 | 需确认 |
| 决定 | 客户或负责人做出的选择（"就按方案 B""定了"） | 需确认 |
| 变更触发 | 会改变方案、报价或执行的要求 | 需确认 |
| 待办 | 有人承诺或被要求做的事，带时间 | 需确认 |
| 背景 | 客户的组织、目的、历史 | 仅记录 |
| 偏好 | 喜欢或不喜欢什么 | 仅记录（建议写入主卡 §4 或 A06） |
| 资源线索 | 提到的场地、讲师、供应商 | 仅记录（建议写入 A03） |
| 报价线索 | 价格信息 | 仅记录（按报价线索规则） |
| 一般沟通 | 问候、确认收到、催促 | 仅记录或忽略 |

状态判定：

- "大概""可能""考虑""争取""看情况"→ 待确认。
- 明确确认用语（"确认""就这么定""按这个来"），且发言人在 A08 中是决策人或采购负责人 → 建议"已确认"，仍由项目经理标记。
- AI 自己的理解和推测 → 推断，并写依据。

## 变更触发规则

1. 对照主卡 §3 当前有效条件，逐项比较新值。
2. 标出涉及的服务模块（D05 §7），例如人数变化涉及 M03、M04、M05、M11。
3. 按 D06 §4.1 第 3 条判断是否重大：总价变化 ≥ 5%、人数变化 ≥ 10%、日期或地点或主要资源变化、增减服务模块、涉及安全。总价影响无法判断时，按"可能重大"处理。
4. 建议下一步：重大 → SC31；一般 → SC30；执行中 → SC37。

## 冲突规则

- 同一事项有两个以上的值（不同人说法不同，或同一人前后不一）→ 列入建议单"冲突"部分。
- 写出每个说法的来源和时间。
- 建议向谁确认：看 A08 的决策角色。
- 冲突影响方案、报价或承诺时，升级 T1 判断影响。
- 不自行选择其中一个值。

## 报价线索规则

- 供应商的书面报价（文件或明确的报价消息，有有效期）→ 建议录入 A04，价格状态"正式报价"，转 SC22。
- 口头或模糊的价格（"大概三百多"）→ 建议录入 A04，价格状态"参考价"，备注原话。
- 不在建议单里做金额计算。
